# 实现与审计路径

数据流为：可信采集（原始 stdout、stderr、退出状态、范围）→ MoonBit 原文解析 → 必需证据单元 → 内置或外部候选 → 独立内容验证 → 接受、重建或回退 → 原文索引回查。

`src/tap.mbt`、`src/rg.mbt` 定义受支持的原文 profile。每个单元是原始连续行区间，含 required 标记。压缩器 `src/compressor.mbt` 只选择 required 单元；`src/validator.mbt` 不读取它的选择结果，直接扫描候选正文，匹配完整单元、必需覆盖和源行顺序。两者共享原文格式契约，**不构成完全独立的双解析器证明**。因此另设 `evaluation/`：从实际 stdout 建立人工可读的独立证据标注，对照器不读取核心 evidence 或 metrics。

验证中，失败测试的名称、状态和 YAML 诊断作为一个原子块匹配。嵌套 Node TAP 递归校验每级编号/计划和全局统计；顶层分支含任一必要证据时，整个分支作为原子单元保留，维持父子身份关联。最大子深度为 32，避免不可信输入造成无界递归。rg 的 path、line_number、lines 和 submatches 在同一 JSON 行匹配；把路径/行号互换，即使全局字符串集合不变，也不能通过。部分删除可修复，但修复结果再次交给验证器检查；预算不足时不进行第二轮有损裁切。

复杂度受输入/行/深度预算控制：格式解析、完整单元匹配、有序行检查、重建均按输入规模扫描；不调用 LLM 或网络。行与 evidence 文本复制会额外占用内存，当前上限只约束输入规模，不是严格进程 RSS 配额。进程包装器另设 timeout 与总字节采集上限。

原文与候选在切分前先检查行数；原始 JSON 在解析后另扫同对象重复键，避免标准解析器覆盖字段后隐藏矛盾。rg 路径/正文/匹配串统一按字节核对，并拒绝未知字段，避免把潜在错误字段连同可省略边界一起丢弃。这仍是明确受限的格式契约，不是任意 rg 选项兼容层。

`tools/run.mjs` 使用 argv 和 `shell:false` 启动用户明确给定的命令，将两个流分别存入唯一目录。只把 stdout 交给格式核心；stderr 原样交付，不做串流交错顺序推断。`tools/recall.mjs` 根据保存的 SHA-256 校验内容后返回行范围。散列用于本地损坏检测；拥有该目录写权限的人也可改 manifest，不能把它当签名或可信第三方证明。

演示只调用核心 JSON API，HTTP 不提供 shell 执行。可选 OpenCode hook 只在固定版本、显式命令白名单、实际退出元数据存在且未截断时尝试；保存 hook 所见原文。这不代表恢复了 Agent 在 hook 之前已截掉的字节。

统一验收在检查前原子写入 `running`，绑定完整分发输入清单及编译产物；检查结束后再次核对，期间变化则失败。打包从一次读取的冻结字节快照建立 ZIP，解包后运行 portable 验收，再将同一份字节发布到本地 `release/`；验收失败不替换已有归档。测试报告等生成数据单独保留，不能把它们当已认证的线上结果。

当前核心是 MoonBit；生成后的 JS 运行时包含 MoonBit 标准库代码。外围开发/验收/演示代码行数不作为主语言价值证明，主要业务计算的职责和可运行测试才是依据。
